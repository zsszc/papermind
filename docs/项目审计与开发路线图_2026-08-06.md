# PaperMind 项目审计与开发路线图（2026-08-06）

## 1. 审计范围与结论

本次审阅覆盖仓库内全部一方源代码、测试、规格、设计/计划文档、CI、Docker、Electron 与公开配置模板；依赖目录（`venv/node_modules`）、构建二进制、用户论文/笔记/数据库正文和真实 `config.yaml` 不属于逐文件内容审阅范围。敏感配置未读取，两个既有未跟踪文件未修改、未提交。

PaperMind 已不是“Phase 1–3 原型”，而是可运行的本地研究工作台：文献导入/解析/标签/笔记/PDF 批注、SQLite FTS5 + BGE/Chroma 混合检索、RAG 对话/记忆/Skill、论文 DOCX/引用检查/写作台、统计/导出/备份、MCP Server/Client、LangGraph、Deep Review、GraphRAG 与 Langfuse 观测均已有实现。当前主要矛盾已从“功能缺失”转为“桌面安全、数据一致性、前端可靠性、评测真实性和检索质量”。

指标差的主要原因不是单一模型问题：正式 QA 几乎都围绕 paper 1，却已导入 19 篇论文；相关 chunk 动态解析导致跨次趋势不完全可比（历史报告中正例平均 relevant 数从 3.045 增到 3.864，约 +26.9%）；中文/英文关键词打分过于朴素；摘要/正文分块与事实数值检索没有专门策略；路由、chat、agent、eval 使用不同检索链；GraphRAG 不进入当前 eval。`citation_coverage` 的口径与摘要 chunk `c-1` 解析问题已在 Batch 12 修复，详见对应测试报告。

## 5. 仍需修复的问题

### P0：发布前阻断

1. **Electron 安全升级与边界**：Electron 29/electron-builder 24 漏洞；固定 8000 端口只用普通 health 200 判定服务，可能连接到本机伪服务；缺 CSP、导航/window.open/权限拦截、single-instance lock。目标：Electron 43 + builder 26、随机端口 + 每次启动能力令牌、严格会话权限策略、macOS arm64/x64 打包冒烟。
2. **历史数据修复**：先备份，再以 dry-run 展示并修复 4 条孤儿 `paper_tags` 与 2 个脏标签；启动健康接口只报告数量，不泄露数据内容。
3. **上传内容校验**：PDF 只看扩展名，DOCX 缺 ZIP 解压上限；需魔数、页数/解压大小/条目数限制，防伪装文件与 zip bomb。

### P1：可靠性与隐私

1. ChatPanel stale closure 导致图片/联网/Skill 可能用旧状态；图片分析/重新生成的 abort signal 未传递；自动重试可能重复落用户消息并重复计费。
2. 笔记防抖在切页/卸载时可能丢写；WritingDesk 把整段正文放 URL query，存在隐私日志与 414 风险；Axios 30 秒默认 timeout 不适合 60–120 秒 AI 请求。
3. 流式 Guardrail 在 delta 已发出后才清理落库文本，无法阻止原始不安全内容到达 UI；断流/取消时消息计数可能漂移。
4. `image_analyzer.py`、`web_search.py` 仍直接创建 OpenAI client，违反 LLM 唯一入口；MCP client 缓存跨事件循环且缺 lifespan close。
5. 备份需改用 SQLite backup API/一致性快照，避免 WAL 写入期 ZIP 得到不一致数据库。

### P2：质量、测试与维护性

1. QA 扩充到 50–100 条、覆盖至少 8–10 篇真实论文；冻结 stable QA/chunk manifest，使趋势可比。
2. 统一 `/search`、chat、agent、eval 的检索入口；加入中文 token 化、数值/单位归一、BM25/FTS chunk 索引、query expansion，并逐项做消融。
3. 修正 eval 摘要引用正则，拆分 citation precision/recall/F1；建立 `--with-llm` 的 mock CI 与定期真实生成基线。
4. 前端引入 Vitest + Testing Library，Electron 引入启动/退出与 IPC 冒烟；CI 补 Ruff、`pip check`、前端/桌面 npm audit。
5. 长段落 chunk 强制上限；中文无空格分块策略；自动标签/记忆拒绝持久化 LLM 错误串。
6. 清理 762 条弃用警告；优化 Stats/ECharts 与 AntD 大 chunk。

## 6. 新开发路线（按顺序执行）

### Milestone 0：安全发布基线（P0，1–2 批）

- Batch 12：Electron Harness + Electron/builder 升级 + CSP/导航/权限/single-instance。
- Batch 13：随机端口与能力令牌；后端仅接受 Electron 注入令牌（开发模式保持本机直连可用）。
- Gate：Electron 冒烟全绿、两个 npm audit 为 0、重打包后资源清单不含密钥/用户数据。

### Milestone 1：数据自愈与导入安全（P0，1–2 批）

- 数据完整性 dry-run/repair/backup 工具；脏标签清理规则。
- PDF/DOCX 内容签名和资源上限；处理失败可重试且状态可解释。
- Gate：复制库上修复后 `foreign_key_check=0`，原库只在用户确认后执行。

### Milestone 2：前端可靠性 Harness（P1，2–3 批）

- 建 Vitest/Testing Library；先覆盖 ChatPanel、笔记保存、WritingDesk body 请求、PdfViewer。
- 修复 stale closure、abort、幂等 retry、卸载 flush 和请求 timeout。
- Gate：关键交互测试 + lint/build；不以人工点验替代自动测试。

### Milestone 3：RAG 质量闭环（P1/P2，3–5 批）

- 完成 Phase A 人工 QA；冻结 stable 集与数据指纹。
- 统一 RetrievalService；按 keyword/BGE/hybrid/query expansion/graph 做可重复消融。
- 修正生成指标并跑真实 `--with-llm` 基线。
- Gate：Recall@5 ≥ 0.60、Factoid/summary 不再为 0、P95 < 1s（默认无 rerank）、负例拒答率 ≥ 0.90；否则不得继续堆 Agent 功能。

### Milestone 4：Phase H UI 迁移（P2）

- 以已有 UI 设计资产为输入，先写页面/组件视觉回归与交互规格，再逐页迁移。
- 保持现有 API 与本地优先架构；AG-UI 仅在能替代自定义 SSE 且有迁移收益时采用。

Phase Z 云端化从路线移除。若未来确需远程访问，必须先修订宪法并单独完成认证、威胁模型和数据治理，不能以“部署方便”为由打开当前无认证 API。

## 7. 每一批必须遵循的 Harness / SDD / TDD 流程

1. **Harness 基线**：记录当前测试、构建、审计、评测、数据指纹；失败必须可复现。
2. **SDD**：先建 `spec.md`（行为/边界/验收）→ `plan.md`（方案/风险/文件）→ `tasks.md`（2–5 分钟 TDD 微循环）。
3. **RED**：先写失败测试或安全/评测 Harness，并亲眼确认因目标缺陷失败；依赖升级以 audit/build RED 为准。
4. **GREEN**：最小实现，仅让目标验收转绿。
5. **REFACTOR**：只清理本批相关坏味道，同步反向规格。
6. **回归 Gate**：后端 pytest、前端 lint/build、相关 audit；检索变更还必须跑固定 QA eval 并报告差值。
7. **提交纪律**：一个可回退行为一个中文 Conventional Commit；测试绿后立即 push；绝不暂存 `config.yaml`、数据目录、个人文件或未审 QA。
8. **发布 Gate**：安全 P0=0、真实数据先备份、制品资源清单复核、安装/启动/退出/升级冒烟通过后才能出新版本。
