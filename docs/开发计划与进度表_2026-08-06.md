# PaperMind 新开发计划与进度表（2026-08-06）

## 1. 目标与执行原则

本计划承接 Phase A–H 与 Batch 7–11 的既有逻辑。项目当前已经具备完整业务功能，后续主线从“继续堆功能”切换为“先建立可信 Harness，再消除发布阻断，最后以稳定基准提升 RAG 与 UI”。

所有批次严格执行 `Harness 基线 → SDD spec/plan/tasks → TDD RED/GREEN/REFACTOR → 全量回归 → 测试报告 → 中文 Conventional Commit → push`。没有稳定基准时，RAG 变化只记为实验结果，不直接修改生产默认策略。

| 阶段 | Recall@5 | MRR | NDCG@5 | 分类下限 | 延迟 |

| 观察基线（当前动态 qrels） | 0.193 | 0.307 | 0.195 | factoid/summary = 0 | P95 149ms |
| 稳定基准建立后首个门禁 | 不低于冻结值 | 不低于冻结值 | 不低于冻结值 | 任一类型不得回退 > 0.05 | warm P95 < 1s |
| RAG 阶段完成目标 | ≥ 0.60 | ≥ 0.50 | ≥ 0.50 | factoid/summary Recall ≥ 0.40 | warm P95 < 1s |

当前质量选择使用 18 篇真实论文、72 条已审 QA 的私有 Benchmark v1；train/dev/holdout 各 24 条。Batch 18 只在 dev 选型，不再读取已经于 Batch 17 验收过的 holdout。有效重建后的 hybrid dev 达到 Recall@5=0.625、MRR=0.394、NDCG@5=0.452；这仍是开发集结果，不能替代新的盲测质量承诺。
