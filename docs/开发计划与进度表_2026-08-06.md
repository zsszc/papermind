# PaperMind 新开发计划与进度表（2026-08-06）

## 1. 目标与执行原则

本计划承接 Phase A–H 与 Batch 7–11 的既有逻辑。项目当前已经具备完整业务功能，后续主线从“继续堆功能”切换为“先建立可信 Harness，再消除发布阻断，最后以稳定基准提升 RAG 与 UI”。

所有批次严格执行 `Harness 基线 → SDD spec/plan/tasks → TDD RED/GREEN/REFACTOR → 全量回归 → 测试报告 → 中文 Conventional Commit → push`。没有稳定基准时，RAG 变化只记为实验结果，不直接修改生产默认策略。

## 3. RAG 指标阶段目标

| 阶段 | Recall@5 | MRR | NDCG@5 | 分类下限 | 延迟 |
|---|---:|---:|---:|---|---|
| 观察基线（当前动态 qrels） | 0.193 | 0.307 | 0.195 | factoid/summary = 0 | P95 149ms |
| 稳定基准建立后首个门禁 | 不低于冻结值 | 不低于冻结值 | 不低于冻结值 | 任一类型不得回退 > 0.05 | warm P95 < 1s |
| RAG 阶段完成目标 | ≥ 0.60 | ≥ 0.50 | ≥ 0.50 | factoid/summary Recall ≥ 0.40 | warm P95 < 1s |

当前质量选择使用 18 篇真实论文、72 条已审 QA 的私有 Benchmark v1；train/dev/holdout 各 24 条。Batch 20 仍只在 dev 选型，没有读取或运行 holdout。共享生产 hybrid dev 达到 Recall@5=0.625、MRR=0.39375、NDCG@5=0.4517186825，factoid Recall=1/3，P95=275.7ms；这仍是开发集结果，不能替代新的盲测质量承诺。

Batch 21 的同论文 `±2` 语义邻域候选在 dev 保持 Recall@5=0.625，但 MRR/NDCG 降至
0.36389/0.43005，factoid 仍为 1/3，因此多指标 Gate 正确拒绝晋级。Batch 22 改为先在
train 冻结 query expansion，再对 dev 只做一次晋级判断；继续不读取或运行 holdout。

Batch 22 的 bilingual v2 在 train 与 v1 的四项质量指标完全相同（0.66667/0.42361/
0.48529，factoid=0.50），未达到至少新增 1 题的预设门槛，因此没有运行 dev。下一步先
收敛 thesis/deep_review 检索旁路并审计 chunk/section 元数据，不继续在 dev 上调词表。

Batch 22B–22G 完成共享消费者收敛、跨块证据修正、细粒度/Parent-Child/Weighted-RRF
消融；候选均按 train Gate 停止。Batch 22H 的确定性 HNSW 在 train 消除了跨进程排序抖动，
但配对 dev 四项指标与生产基线完全相同，未满足严格提升条件，因此没有激活。Batch 22I
的三路锚点候选在同次 train 遍历中 Recall/factoid 均零提升，MRR/NDCG 反而回退
0.025/0.0203，因此停止且未查看 dev。v1 train/dev 已经支撑多轮假设，下一批先从
`papers/` 中尚未覆盖的真实论文构建盲化 Benchmark v2，不再围绕已观察集调规则。

Batch 22J 的只读盘点确认 `papers/` 有 36 个物理 PDF，但只有 19 份唯一二进制内容，
其中 17 个为重复副本；v1 已覆盖 18 份，当前仅 1 篇满足 v2 纳入条件，低于预注册的
12 篇门槛。系统因此没有生成 v2 QA/split、没有运行盲化基线，也没有消费 holdout。
因此先以 Batch 22K 提供只读聚合就绪度观测，并等待补充至少 11 篇真正不同的新论文。

Batch 22K 已把同一覆盖核心同时接入 CLI 与本地 API，统计页现在独立显示
PASS/WAIT/不可用三态；真实 API 返回 WAIT、36 个物理 PDF、19 份唯一内容、17 个副本、
v1 覆盖 18、合格 1、尚缺 11。API 使用严格白名单和 `Cache-Control: no-store`，异常时
未知计数为 null，不返回身份或哈希。Electron 运行时继续排除整个 `backend/eval`，缺失
私有身份制品的发行版只显示不可用。下一批先建立完全公开、离线的生成 Guardrail Harness；
真实论文的 Kimi smoke 继续等待独立的内容出站授权。

Batch 23A 已将生产 `[^n^]` 解析与离线评测收敛到同一纯 Guardrail，主聊天
stream/non-stream 与 regenerate 都只发布实际引用子集。前端把 delta 视为
provisional，finished 携带清洗后全文并原子替换；error/EOF/取消不保留半条
回答。公开生成 Gate 的 citation P/R/F1 和负例拒答率均为 1.000，协议违规为 0。
Batch 23C 随后把 LLM 错误串、空输出和中途异常统一为脱敏失败终态，assistant、引用
与计数只在成功事务提交；前端引用归属到具体消息，图片/文本 error 与取消均丢弃半条。
Batch 23D 进一步让 deep-review 只在成功终态创建新会话，失败或取消不再留下空会话；
regenerate 使用消息 revision、进程内 single-flight 和数据库条件更新，冲突、目标删除、
断流或取消后由前端重新读取历史对账，迟到结果不能覆盖已切换会话。
Batch 23E 将这些契约移入独立进程和真正的文件 SQLite/WAL：七个场景分别使用新连接，
commit failure 必须命中真实写事务后才能通过，报告不含正文、路径或异常；网络、子进程、
私有路径与真实模型服务调用均为 0。生成 Guardrail 另由零依赖 `python -S` CI job 执行。
下一个生成质量阶段 Batch 23B 仍须单独的真实内容出站授权；未授权前可进入 Batch 24
的纯本地 UI/E2E 发布候选工作。
