# Batch 16 规格：Electron 后端身份边界

## 1. 背景

Electron 生产包当前固定连接 `127.0.0.1:8000`，并把任意 `/api/health` HTTP 200 当作 PaperMind 后端。若端口已被无关或恶意本机服务占用，桌面端可能把论文、图片或对话请求发送给错误进程。固定端口也会与开发实例、其他 PaperMind 进程冲突。

Batch 15 已完成窗口与依赖安全，本批补齐桌面壳到后端进程的实例身份。此机制是本地进程能力边界，不是用户登录、账号或多租户权限，不违反单用户零权限原则。

## 2. 行为规格

### S1：每次应用启动的实例身份

- Electron 生产主进程每次启动生成不可预测的 256-bit 能力令牌和独立实例 ID。
- 令牌不得写入 URL、命令行参数、日志、配置文件或用户数据目录；只通过后端子进程环境和受限 IPC 传递。
- 后端重启沿用当前应用实例的端口、令牌和实例 ID；完全退出再启动必须轮换。

### S2：随机回环端口

- 生产模式从 `127.0.0.1` 动态选择空闲高位端口，并仅绑定回环地址。
- 开发模式保持现有 8000 端口和无令牌直连，浏览器、pytest、Docker、MCP 开发流程不受影响。
- 端口选择与后端 spawn 参数由纯函数/可注入依赖测试，不依赖真实 GUI。

### S3：后端能力校验

- 当且仅当 `PAPERMIND_API_TOKEN` 非空时，后端对 HTTP 请求要求 `X-PaperMind-Token` 恒定时间匹配。
- CORS 预检 `OPTIONS` 可无令牌通过；其他 API、静态文件、文档与 MCP 路径统一受保护。
- 缺失或错误令牌返回稳定 401 通用响应，不回显期望值或输入值，不写入访问日志正文。
- 无令牌环境保持现有行为，避免把桌面内部能力机制扩张成产品账号权限。

### S4：身份化健康握手

- Electron readiness probe 必须携带令牌，并解析 JSON；仅当 HTTP 200、`status=ok` 且响应 `instance_id` 与预期相同时视为自己的后端。
- 占用随机端口但返回 200、错误 JSON、错误实例 ID 或忽略令牌的假服务均不得被接受。
- health 响应不返回能力令牌。

### S5：渲染器最小暴露与前端适配

- preload 仅向当前主窗口提供异步只读运行配置 `{apiBaseUrl, apiToken}`，不暴露环境变量或 Node 能力。
- 主进程 IPC 只响应受信主窗口发送者；其他 webContents 请求被拒绝。
- axios、SSE、图片分析、论文建议、PDF 加载与下载等全部后端请求统一携带能力头。
- CSP 只放行 `127.0.0.1` 的动态端口，不扩大到外部主机或任意外部脚本。

## 3. 验收标准

1. 后端无令牌兼容、正确/错误令牌、OPTIONS、static 和 health 实例 ID 均有 RED→GREEN 测试。
2. Electron 覆盖令牌长度、随机端口、spawn 环境净化和身份化健康探测；假 200 服务必须失败。
3. 前端覆盖运行配置初始化、统一请求头和 Electron 配置失败的安全行为。
4. 后端 pytest、前端 test/lint/build、Electron node:test 与两端 audit 全绿。
5. 运行无真实 LLM 的回环集成 smoke：随机端口后端只接受正确令牌，错误令牌/实例 ID 被拒绝，退出后端口释放。
