# Batch 34 规格：52 篇全覆盖真实 QA v3

## 1. 冻结事实与目标

1. 当前 `papers/` 有 102 个 PDF、52 份唯一内容和 50 个重复副本；主库有 52 篇论文、
   5893 个 chunk，全部唯一论文已经导入，不重复喂入物理副本。
2. 既有 v1 覆盖 18 篇；v2 的冻结论文集合覆盖另外 34 篇，但现有 40 条 QA 只来自其中
   27 篇。v3 必须覆盖全部 52 篇唯一论文。
3. v1 已消费过的论文和 QA 在 v3 一律视为 train；v2 保持已冻结的 12/11/11
   train/dev/holdout 论文分配，不允许论文跨 split。
4. 对 v2 的 34 篇论文补题，直到每篇至少有 2 条正例；只补缺口，不改写既有 QA。
5. QA 必须由代理本地阅读 PDF/解析文本后编写，不调用 Kimi 或其他外部服务；每条正例使用
   至少 20 字符、在目标论文中唯一解析的逐字证据。数值、表格或图示题须渲染对应页面抽查。

## 2. 作者与留出隔离

- 在补题前生成只含冻结 UID/SHA/split/本地路径的私有任务单。
- train/dev 可由独立作者代理分片编写并交叉验证；holdout 由专用作者代理编写。
- 主代理不得打开或复述 holdout 的问题、答案或证据正文；自动校验器只输出去标识化聚合。
- v3 holdout 在候选通过 train 与一次 dev 前不得运行；运行时仍需一次性 claim。

## 3. 质量与评测 Gate

1. schema、QA ID、规范化问题文本、证据和论文身份均唯一；所有证据 100% 在当前
   SQLite/PDF/冻结 manifest 下唯一解析。
2. v2 34 篇每篇至少 2 条正例；与 v1 合并后覆盖 52/52 唯一论文。
3. 先固定当前生产 `hybrid + bm25-bilingual + rerank=false` 的 train/dev 基线，不调用 LLM。
4. 低质量判定沿用项目目标：Recall@5 <0.60、MRR <0.50、NDCG@5 <0.50、
   span coverage@5 <0.60 或任一主要题型 Recall <0.40。
5. 若基线偏低，只根据 train 去标识化失败归因冻结一个候选；train 全指标通过后只运行一次 dev。

## 4. 验收标准

- [ ] AC1：覆盖缺口规划器与隐私聚合先 RED 后 GREEN。
- [ ] AC2：补充 QA 使 v2 34/34 篇每篇至少 2 条，证据全部唯一解析。
- [ ] AC3：v3 合并后覆盖 52/52 篇，holdout 正文对主代理保持封存。
- [ ] AC4：当前生产 train/dev 基线与低指标归因形成私有报告。
- [ ] AC5：若需改进，候选严格 train-first；三端回归、测试报告、提交和 push 完成。

## 5. 非目标

- 不删除 50 个重复 PDF，不覆盖真实数据库、PDF 或生产向量库。
- 不把私有 QA、论文身份、标题、路径、DOI、SHA 或证据正文提交到 Git。
- 不因本轮授权读取论文而推定获得向外部模型发送论文内容的授权。
