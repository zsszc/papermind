# Batch 23C 规格：生成失败事务闭环

## 1. 目标

把文本对话、重新生成与图片分析的流式失败从“正文中的错误字符串”提升为明确失败终态，
确保数据库、SSE 与前端消息展示在错误、取消和协议不完整时保持一致，且不泄露内部异常。

## 2. 范围

- 主聊天识别 LLM 的历史带内错误串，并转换为固定脱敏错误；不得发送该错误串或保存助手消息。
- 主聊天在成功保存助手消息后才增加助手计数；失败或取消后 `message_count` 等于实际消息数。
- 非流式聊天在 LLM 失败时返回固定脱敏 503，保留已提交的用户问题但不保存助手回答。
- 重新生成失败、取消或空结果时保留原助手正文与引用，不发送成功终态。
- 前端将引用绑定到每条助手消息；失败、取消或不完整 finished 不得提交 provisional 正文或引用。
- 图片流与文本流采用相同的半条丢弃、固定失败/停止占位规则。
- 全部测试使用 mock / 公开合成数据；不调用 Kimi、联网搜索、Embedding，不读取私人语料或密钥。

## 3. 硬 Gate

- SSE 失败只允许一个固定 `{error}` 终态，之后不得出现 `finished`；响应不得含错误串中的内部细节。
- 主聊天失败可保留用户消息，但助手消息数必须为 0，`conversation.message_count` 必须等于实际消息数。
- 重新生成失败时目标消息的 `content + citations` 与请求前完全相同。
- 空白生成视为失败，不得保存空助手消息或发布成功 finished。
- 前端只有携带字符串 `content` 的首个 finished 才能提交成功终态；error、EOF、cancel 均回滚 provisional。
- 每条引用只显示在所属助手消息下，不得以面板级状态误归属给其他回答。

## 4. 非目标

- 不改变 LLM 服务对其他历史消费者的带内错误串兼容契约。
- 不自动重放非幂等聊天请求，不改变检索排序、模型、温度或提示词。
- 不执行真实论文 Kimi smoke；该步骤仍需单独的内容出站授权。
