# Batch 9：配置持久化与本机部署边界规格说明书

## 1. 背景与目标

PaperMind 是无登录的本地单用户应用。配置保存必须确保真实 API Key 只写入私有运行时配置，任何写入失败都不能破坏原文件或留下内存/磁盘不一致；宿主机启动入口必须仅监听回环地址，避免无认证 API 被局域网直接访问。

## 2. 范围

### 2.1 包含

- `Config.save()` 的目标选择、原子替换与文件权限。
- `PUT /api/settings` 保存失败时的内存回滚。
- 开发脚本、README 和 Docker Compose 的宿主机监听边界。
- Docker 手工运行文档中的端口绑定示例。

### 2.2 非目标

- 不引入登录、权限或多租户。
- 不改变容器内部 Uvicorn 的监听地址；容器仍需监听其网络接口，由宿主机端口映射限制访问范围。
- 不在本批次实现 Electron 随机端口或能力令牌。

## 3. 行为契约

### 3.1 `Config.save(self)`

- 若当前加载路径为 `config.yaml.example`，保存目标必须改为同目录的 `config.yaml`，示例模板保持不变。
- 写入采用同目录临时文件加原子替换；序列化或落盘失败时，原配置内容保持不变。
- 成功保存的配置文件权限为仅当前用户可读写（`0600`）。
- 成功后 `config_path` 指向实际写入的 `config.yaml`。

### 3.2 `PUT /api/settings`

- 保存成功时内存与磁盘同时反映新值。
- 保存失败时返回脱敏的 HTTP 500，并把内存配置恢复到请求前状态。

### 3.3 本机监听边界

- `scripts/start-demo.sh` 和 README 的开发命令使用 `127.0.0.1`。
- Docker Compose 对外发布的 PaperMind 后端和 Langfuse 控制台端口绑定 `127.0.0.1`。
- `docs/DEPLOY.md` 的 `docker run` 示例显式绑定 `127.0.0.1`。

## 4. 边界条件与错误处理

| 场景 | 期望行为 |
|------|----------|
| 只加载了示例模板后保存 | 新建私有 `config.yaml`，不修改 `.example` |
| YAML 序列化失败 | 原文件字节不变，异常向上抛出 |
| 设置接口落盘失败 | 响应不含异常原文，内存回滚 |
| Docker 容器内部监听全部接口 | 允许；宿主机发布端口仍仅绑定回环 |

## 5. 依赖

- 上游：PyYAML、`pathlib`、FastAPI 设置路由、Docker Compose。
- 下游：设置弹窗、LLM 服务、开发与容器启动流程。

## 6. 验收标准（可测试）

- [x] AC1：从 `.example` 回退配置保存时，示例文件不变且生成 `config.yaml`。
- [x] AC2：配置序列化失败不破坏既有文件。
- [x] AC3：成功保存的配置权限为 `0600`。
- [x] AC4：设置保存失败后内存配置恢复，响应继续脱敏。
- [x] AC5：仓库提供的宿主机启动入口和端口映射均限制在回环地址。

## 7. 现有测试覆盖与盲区

- 已覆盖：生产数据目录复制模板、已有配置不覆盖、异常响应脱敏。
- 盲区：原子写入、私有权限、example 防污染、失败回滚及部署监听边界。

## 8. 关键设计决策

- 使用同目录临时文件保证原子替换不跨文件系统。
- 配置含明文密钥，因此不依赖系统默认 umask，显式收紧到 `0600`。
- 维持零权限架构，通过回环监听落实本地信任边界。
