# services/cache.py（轻量级内存缓存 SimpleCache）规格说明书

> 本文件描述 `backend/app/services/cache.py` 的**行为契约**（做什么），不描述实现细节。
> 依据源码实际内容反向工程整理（2026-08-04）。

## 1. 背景与目标

语义检索每次都要跑一遍 BGE-M3 查询编码 + ChromaDB 查询，成本在百毫秒到秒级；对话与检索页的高频重复查询（同一 query 反复提交）会造成明显浪费。本模块提供一个**进程内、带 TTL 与容量上限**的极简内存缓存，当前唯一实际用途是为 `retrieval.py` 的语义检索结果提供 60 秒缓存。

设计动机：单用户、单进程架构（宪法第 4 条）下无需 Redis 等外部缓存；一个 dict + 过期时间戳即可满足，依赖为零、行为可预测。模块 docstring 提到「LLM 常见回答」缓存，但该用途**至今未落地**（全项目无任何 LLM 结果走此缓存）。

## 2. 范围

### 2.1 包含

- `SimpleCache` 的 `get` / `set` / `cached` 三个公开行为
- TTL 过期语义（惰性删除）与容量驱逐策略
- `_make_key` 默认键生成规则
- 模块级全局实例 `cache = SimpleCache(default_ttl=300, max_size=1000)`

### 2.2 非目标

- 跨进程 / 持久化缓存（重启即失效，属刻意设计）
- 缓存失效 API：本模块**不提供** `delete` / `clear` / 按前缀失效等任何主动失效手段
- 语义检索缓存键的具体拼法与 60 秒 TTL：归 `services/retrieval.py` 规格（本模块只提供机制）
- 并发控制：本模块**无锁**，不保证并发语义（见第 4、8 节）

## 3. 行为契约

### 3.0 模块级副作用

模块底部执行 `cache = SimpleCache(default_ttl=300, max_size=1000)`：导入即创建全进程唯一缓存实例。默认 TTL 300 秒、容量上限 1000 条。

### 3.1 `SimpleCache.__init__(self, default_ttl: int = 300, max_size: int = 1000)`

- **输入**：`default_ttl` 默认存活秒数；`max_size` 容量上限（触发驱逐的阈值）
- **输出**：空缓存实例（内部为普通 dict）
- **副作用**：无

### 3.2 `SimpleCache.get(self, key: str) -> Any`

- **输入**：字符串键
- **输出**：命中且未过期 → 存入时的 `value` 原样返回；未命中或已过期 → `None`
- **过期语义**：惰性删除——访问时发现 `expires < time.time()` 则顺手从 dict 移除该键再返回 `None`；未被访问的过期项**会一直滞留**（直到 `set` 触发驱逐）
- **注意**：存入 `None` 与未命中**不可区分**（都返回 `None`）；存入 `0` / `""` / `[]` 等 falsy 值可正常返回，不受影响
- **副作用**：可能删除一个过期键

### 3.3 `SimpleCache.set(self, key: str, value: Any, ttl: Optional[int] = None)`

- **输入**：`ttl=None` 或 `ttl=0` 时按 `default_ttl`（`ttl or self.default_ttl` 的 falsy 语义）
- **后置条件**：`self._store[key] = {"value": value, "expires": time.time() + ttl}`——同键重复 set 直接覆盖并**刷新过期时间**
- **容量驱逐**（仅在 `len(self._store) >= self.max_size` 时触发，按序执行）：
  1. 先扫描全表，删除所有已过期键，**至多删 100 个**；
  2. 若一个过期键都没有，则删除 `expires` 最小（**最早将过期**）的那一项，然后插入。
- **命名纠偏**：代码注释自称「简单 LRU」，实际**不是 LRU**——不记录访问时间，驱逐依据是过期时间戳而非使用热度；刚被频繁访问但 TTL 最短的项会被优先驱逐
- **副作用**：可能删除 1~100 个键；写新键

### 3.4 `SimpleCache._make_key(self, *args, **kwargs) -> str`

- **输出**：`md5(str(args) + str(sorted(kwargs.items()))).hexdigest()`——32 位十六进制串
- **语义**：以参数的 `str()` 表示做键。对基本类型稳定；对自定义对象依赖其 `repr`（默认含内存地址），同一逻辑实体跨调用可能得到不同键
- **稳定性**：`kwargs` 先按键排序再拼接，故关键字参数顺序不影响键；`md5` 输出在全进程一致（与 Python 内置 `hash()` 的加盐随机化不同，键跨进程/跨重启稳定）

### 3.5 `SimpleCache.cached(self, ttl: Optional[int] = None, key_func: Optional[Callable[..., str]] = None)`

- **定位**：方法级缓存装饰器工厂
- **输入**：`ttl` 透传给 `set`；`key_func(*args, **kwargs) -> str` 自定义键生成，缺省走 `_make_key`
- **包装后行为**：调用时先 `get(cache_key)`，命中（非 `None`）直接返回；未命中执行原函数并 `set(cache_key, result, ttl)` 后返回
- **已知契约限制**：
  1. `wrapper` 是**同步函数**，装饰 async 函数会把 coroutine 对象当值缓存，语义错误——本装饰器仅适用同步函数；
  2. 原函数返回 `None` 时，下次调用视为未命中**会重复执行**（None 不可缓存，见 3.2）；
  3. 无击穿保护：并发 miss 会并发执行原函数（single-flight 缺失）；
  4. 用 `functools.wraps` 保留原函数元数据。
- **使用现状**：**全项目无任何调用方**——当前只有 `cache.py` 自身定义它；`retrieval.py` 用的是裸 `get`/`set`

## 4. 边界条件与错误处理

| 场景 | 期望行为 |
|------|----------|
| 缓存未命中 | `get` 返回 `None`，调用方自行回源 |
| 键已过期但无人访问 | 滞留占容量，直到被 `get` 惰性清除或 `set` 驱逐扫描清除 |
| 容量满且有过期键 | 一次最多清 100 个过期键后插入；极端情况下（过期键 >100 且清完仍满）直接插入，**容量可短暂超过 max_size** |
| 容量满且无过期键 | 驱逐 `expires` 最小的一项（最早将过期者），容量维持 `max_size` |
| 存入 `None` | 可存入，但 `get` 表现同未命中；`cached` 装饰器下会每次重复执行原函数 |
| `ttl=0` | 按 `default_ttl` 处理（falsy 语义），**无法表达「立即过期」** |
| 过期时间点边界 | 判定为 `expires < time.time()`，即恰好等于过期时刻的当次访问仍视为有效 |
| 数据变更（如删文献） | 本模块无失效 API，语义检索缓存最长陈旧 60 秒（TTL 由 retrieval 层设为 60s），期间已删除文献的片段仍可能命中返回 |
| 多线程并发 get/set | 无锁；CPython GIL 保证单个 dict 操作原子，但「检查容量→驱逐→插入」等多步操作存在竞态，最坏后果是个别键丢失或容量瞬超，不会崩溃——单用户场景下视为可接受 |
| 进程重启 | 全部缓存丢失（纯内存，刻意设计） |

## 5. 依赖

- **上游依赖**：仅标准库 `hashlib` / `time` / `functools` / `typing`，零第三方、零配置项
- **下游消费者**：
  - `services/retrieval.py`（`VectorStore.search`）：唯一实际消费者，键形如 `semantic_search:{hash(query)}:{top_k}:{hash(str(sorted(filters.items())))}`，`ttl=60` 秒
  - `cached` 装饰器与 `_make_key`：当前无消费者（预留能力）

## 6. 验收标准（可测试）

- [ ] AC1：`set` 后 TTL 内 `get` 返回原值；超过 TTL 后 `get` 返回 `None` 且该键被从存储中移除
- [ ] AC2：`set` 不传 `ttl` 时按构造的 `default_ttl` 过期；显式传 `ttl` 时按显式值过期
- [ ] AC3：容量达到 `max_size` 且存在过期键时，`set` 优先清除过期键（不多于 100 个）后插入；无过期键时驱逐 `expires` 最小项，容量不超过 `max_size`
- [ ] AC4：同键重复 `set` 覆盖旧值并刷新过期时间
- [ ] AC5：`cached` 装饰的函数相同参数只执行一次，后续命中缓存；`key_func` 提供时以其返回值做键；`kwargs` 顺序不影响默认键
- [ ] AC6：原函数返回 `None` 时不形成有效缓存，每次调用都真实执行
- [ ] AC7：存入 falsy 非 None 值（`0`/`""`/`[]`）可正常命中返回

## 7. 现有测试覆盖与盲区

- **已覆盖**：**零**——`backend/tests/` 15 个测试文件中无任何对本模块的引用；`retrieval.py` 的缓存路径在检索测试里也被 `_StubVectorStore` 整体桩掉，不会触达本模块
- **盲区**：
  - TTL 过期与惰性删除语义（AC1/AC2）无测试（**高**，核心契约）
  - 容量驱逐两条路径（过期优先 / 最早过期兜底）及「至多清 100 个」上限无测试（**高**）
  - 「注释称 LRU、实为最早过期驱逐」的行为无测试固化，存在被后人「修正」成真 LRU 而改变行为的风险（**中**）
  - `cached` 装饰器全路径（命中/未命中/key_func/None 不缓存）无测试（**中**）
  - 无失效 API 导致的语义检索最长 60 秒陈旧窗口无端到端测试（**中**，删文献后检索结果仍含旧片段）
  - `ttl=0` 被当作默认 TTL 的 falsy 语义无测试（**低**）
  - `_make_key` 对 kwargs 排序的稳定性、对自定义对象 repr 的敏感性无测试（**低**）
  - 并发竞态（无锁）无测试，属已知接受项（**低**）

## 8. 关键设计决策

- **纯内存、无持久化、无失效 API**：单用户单进程下，缓存一致性靠「短 TTL（检索层 60 秒）自然过期」换取实现极简；代价是数据变更后存在最长 60 秒的检索结果陈旧窗口——若未来引入「删除文献后立即失效检索缓存」的需求，必须给本模块新增 `delete`/按前缀清除能力，而不是绕过它
- **惰性过期**：没有后台清扫线程，过期项靠访问时清除与 `set` 时驱逐顺带清理，避免额外线程（宪法第 4 条单进程简单架构）
- **驱逐策略是「最早过期优先」而非 LRU**：实现只需比较 `expires` 时间戳，无需维护访问顺序；~~代码注释误写为「简单 LRU」~~ 注释已于 Batch7-F7（随 fd84873 后一批）修正为与实际行为一致
- **`md5(str(args))` 默认键**：对可哈希基本类型足够稳定且跨进程一致（区别于加盐的内置 `hash()`），但当前唯一消费者 `retrieval.py` 自行拼键并未使用它；`_make_key`/`cached` 属预留能力，删除前需确认无动态调用方
- **无锁**：单用户低并发下，GIL + 偶发竞态（个别键丢失）的后果可接受，换零同步开销；不得在高并发改造中默认沿用此假设
